# Architecture

`map-zero` separates the data pipeline from the rendering helpers:

- Source adapters provide typed layer schemas and EPSG:4326 features to a generic GeoPackage writer. The built-in OSM adapter parses PBF; applications can supply other sources.
- OpenLayers uses generic MVT/PMTiles from that GeoPackage. Cesium uses independently exported static 3D Tiles from the same source.
- Styles live outside the GeoPackage as JSON.
- OpenLayers and Cesium helpers add map-zero packages to existing viewers without owning the application.

For application-facing definitions and a complete example, see [Custom geospatial data](custom-data.md).

## Core Pipeline

- `src/cli.js`: command wiring, argument parsing, terminal progress output.
- `src/build.js`: package build orchestration and output folder creation.
- `src/osm.js`: streamed OSM PBF scan, temporary SQLite build store, geometry extraction.
- `src/layers.js`: logical layer definitions, OSM tag matching, layer property normalization, including subtle 2D terrain edge overlays for coastline, beach/sand, and cliffs.
- `src/gpkg.js`: GeoPackage creation and incremental feature writes.
- `src/gpkg-read.js`: readonly GeoPackage metadata and tile feature queries.
- `src/geometry-read.js`: GeoPackage binary geometry decoding.

### Public GeoPackage API

Node consumers can use stable package subpaths:

```js
import { openGeoPackageWriter, writeGeoPackage } from 'map-zero/gpkg';
import { openGeoPackageReader } from 'map-zero/gpkg-read';
import { createManifest, resolveManifestLayers, isLayerInZoomRange } from 'map-zero/manifest';
```

These export the existing implementations directly. Legacy deep imports such as
`map-zero/src/gpkg.js` remain available. The writer accepts typed layer schemas;
reader and manifest helpers accept public IDs mapped to independent SQL tables.
No adapter-specific schema or conversion logic is included in these entry points.

For reproducible exports, `openGeoPackageWriter(path, layers, bbox, { lastChange })`
and `writeGeoPackage(path, features, layers, bbox, { lastChange })` accept a fixed
ISO UTC timestamp with milliseconds. Omitting it preserves current-time metadata.
Timestamp validation happens before replacing an existing file. Byte identity
requires identical input order/options and the same SQLite/software environment.

`openGeoPackageReader(...).getLayerStats()` performs unfiltered SQL counts and
RTree inspection for declared layers without materializing features. It returns
`id`, `table`, `featureCount` and `rtree` details: registration, entry count,
missing/orphan IDs, invalid bound order, `rtreecheck` result and `verified`.
Verification requires every feature row to have an index entry; it targets the
non-null geometry tables generated by this writer. It checks structure and ID
coverage, not each envelope against decoded geometry. Normal tile reads incur
none of these inspection queries unless the caller requests them.

### Public PMTiles export API

`exportPmtiles` from `map-zero/export-pmtiles` exposes the existing exporter:

```js
import { exportPmtiles } from 'map-zero/export-pmtiles';

const result = await exportPmtiles({
  packageDir: './dataset', minZoom: 4, maxZoom: 15, workers: 1
});
```

The directory contains `manifest.json` and its referenced GeoPackage. Optional
arguments are `out` (inside that directory), `force` and `onProgress`. Export
defaults remain z8..16; adapters should explicitly pass their desired range.
The result contains `outPath`, `minZoom`, `maxZoom`, `estimatedTiles`,
`writtenTiles`, `skippedEmptyTiles`, `prunedEmptyTiles`, `visitedTiles` and
`outputBytes`. The manifest's `tiles`
entry is updated after export. Descriptor zoom bounds intersect the requested
range and unknown layer IDs use the generic MVT policy. No source-specific
adapter dependency or new encoder behavior is introduced by this public export.

`tilePlanning` defaults to `rtree`. The exporter streams visible feature RTree
envelopes via `reader.iterateFeatureBounds(layerId, zoom)` and merges y intervals
per x column, without enumerating the rectangular area just to plan it. A 50,000
raw-interval budget per zoom bounds memory; exceeding it falls back to the prior
RTree block walk. All eligible source tables are a conservative superset for OSM
aliases/labels. The plan includes the original edge margin and package clipping.
Plans are released between zooms and shared by parent-side worker dispatch.

`pruneEmptyTiles` defaults to true and enables subsequent RTree block occupancy
checks. `tilePlanning: 'bbox'` selects the old global coverage; disable pruning
separately for a full baseline. Missing source indexes retain the old traversal
and error behavior. Neither step decodes geometry or adds domain-specific policy.

The result also includes `sparsePlanCandidates`, `planExcludedTiles` and per-zoom
`planning` statistics (mode, reason, extent count, interval count, tile count,
duration). `estimatedTiles` remains the theoretical bbox count. Accounting is:

```text
estimatedTiles = planExcludedTiles + sparsePlanCandidates
sparsePlanCandidates = prunedEmptyTiles + visitedTiles
estimatedTiles = skippedEmptyTiles + writtenTiles
```

The 100,000-candidate guard now applies to the cumulative sparse/fallback plan.
Large line and polygon envelopes still overestimate occupied cells, and very
large feature collections can hit the interval budget. Fallback is bounded in
memory, not a promise of fast global export. MVT resource budgets and archive
entry memory remain unchanged.

### Optional feature zoom visibility

Manifest descriptors can opt into integer feature visibility columns:

```js
{ id: 'observations', table: 'survey', minZoom: 4, maxZoom: 14,
  featureZoom: { minColumn: 'first_zoom', maxColumn: 'last_zoom' } }
```

Both mappings are optional individually; at least one is required when the
object is present. The reader validates that mapped columns exist and declare
`INTEGER`. NULL endpoints mean unbounded; both comparisons are inclusive.
Column names have no implicit/reserved semantics, so existing OSM packages
without the descriptor behave unchanged.

`getTileFeatures(id, bbox, {zoom})` applies those bounds in SQL before decoding.
MVT scopes normal and policy reads to the current zoom. Unzoomed inspection
reads all rows. `iterateFeatureBounds(id, zoom)` shares the same SQL predicate
and streams only RTree envelopes. Layer bounds still provide coarse visibility
and PMTiles aggregate metadata; feature intervals further restrict rows. Writer
schemas use ordinary INTEGER columns and require no OSM/ARINC-specific additions.

### GeoPackage Layer Descriptors

The public `map-zero/gpkg` writer accepts storage descriptors independently of
OSM. Both `openGeoPackageWriter(path, descriptors, bbox)` and
`writeGeoPackage(path, featuresByLayer, descriptors, bbox)` take an array such as:

```js
const descriptors = [{
  id: 'airspaces',
  geometryType: 'POLYGON',
  columns: {
    id: 'TEXT',
    name: 'TEXT',
    lowerLimitM: 'REAL',
    upperLimitM: 'REAL',
    priority: 'INTEGER'
  }
}];
```

The writer creates `fid` (integer primary key) and `geom` (geometry blob).
Descriptor columns are nullable `TEXT`, `INTEGER`, or `REAL`, using SQLite
affinity; missing properties are stored as NULL. `fid`, `geom`, and SQLite rowid
aliases are reserved column names. Layer names cannot use the `gpkg_`, `sqlite_`,
or `rtree_` prefixes. Descriptors are validated before replacing an existing file.

Geometries use EPSG:4326 XY coordinates. Supported geometry types are `POINT`,
`LINESTRING`, `MULTILINESTRING`, `POLYGON`, `MULTIPOLYGON`, and `GEOMETRY` for mixed
tables. Callers supply compatible geometries; the writer does not convert them.
The incremental writer retains `insertFeature(layerId, feature)`,
`transaction(fn)`, `counts()`, and `close()`. RTree entries are populated during
insertion; extension metadata and triggers are installed on close.
Non-empty `feature.properties.id` values are deduplicated per layer for the open
writer's lifetime, including numeric zero; missing, null, or empty ids are not
deduplicated. Opening a writer always creates a new file, not an append session.

OSM callers convert their canonical layer ids with
`geoPackageLayersForOsm(layerIds)` from `src/layers.js` before calling either
writer function. This replaces the internal writer's previous `string[]`
argument. `buildPackage`, the CLI, and OSM table schemas remain unchanged.
`src/gpkg-read.js` discovers table metadata and
preserves numeric values; use `{ layers: ['airspaces'] }` in its manifest input
to read an external layer. Unknown layer IDs use generic MVT/PMTiles cartography. Known OSM IDs retain the default OSM policy; 3D export retains its existing strategies.

Existing writer limitations remain: deduplication retains ids in memory, and a
failed transaction rolls back SQLite rows but does not restore the in-memory
counts or seen ids. Recovery and retry after rollback need a separate change;
callers should abort the build on transaction failure. RTree creation still
falls back to an unindexed table if SQLite cannot create the virtual table,
while the tile reader requires an RTree.

### Manifest Layer Descriptors

Version 1 manifests accept strings, descriptors, or a mixture of both:

```js
layers: [
  'roads',
  {
    id: 'regions',
    table: 'region_data',
    geometryType: 'POLYGON',
    minZoom: 4,
    maxZoom: 12,
    source: 'survey'
  }
]
```

`id` is the public identity used by styles, HTTP queries, MVT source layers,
PMTiles metadata, and viewer controls. `table` is the GeoPackage table and
defaults to `id`. Multiple public ids can refer to the same table. `geometryType`
and `source` are optional non-empty strings; geometry types use GeoPackage names
such as `POLYGON` or `GEOMETRY`. Source is descriptive metadata, not a loader or
URL to fetch. The GeoPackage reader uses the database's actual geometry type;
viewers can use the manifest type when the database is not available.

`minZoom` and `maxZoom` are optional finite, non-negative numbers, with inclusive
endpoints and `minZoom <= maxZoom`. They constrain vector MVT queries, PMTiles
generation, and 2D vector rendering alongside existing style/OSM restrictions.
They do not change the 3D Tiles subdivision policy or introduce new 3D geometry
strategies. Existing 3D layer strategies now resolve their storage table through
the manifest, including `buildings`.

The shared, browser-safe API is in `packages/core/src/manifest.js` (published as
`@map-zero/core/manifest.js`) and re-exported by `src/manifest.js`:

- `resolveManifestLayers(manifest)` returns copied descriptors with required
  `id` and `table`, preserving optional metadata. A string becomes
  `{ id: value, table: value }`. Missing layers resolve to an empty list; package
  entry points still require the fields they needed previously. Malformed
  descriptors and duplicate public ids throw an error. The helper does not
  canonicalize OSM aliases; existing adapters retain that behavior.
- `isLayerInZoomRange(descriptor, zoom)` checks the optional inclusive bounds.
- `createManifest({ outDir, bbox, layers })` accepts either representation and
  keeps strings as strings, so OSM builds still produce the same version 1
  format. Descriptor entries receive the default `table` when omitted.

Readers, exporters, styles, and viewer controls share this normalization.
Serving a manifest or updating its style/export URLs preserves its layer
representation. No migration is needed for existing packages. Older map-zero
releases that only understand strings need upgrading to consume descriptors.
Direct users of `createNativeVectorStyle(style, options)` can pass
`options.manifest` to apply descriptor zoom bounds and geometry hints; the
Cesium controller supplies this automatically.

## 2D Tile Pipeline

- `src/mvt.js`: generic MVT queries, budgets, generalization, clipping, encoding and statistics.
- `src/mvt-osm-policy.js`: default OSM cartography, SQL query filters, priorities, size thresholds and label layers.
- `src/mvt-utils.js`: shared geometry and stable feature selection helpers.
- `src/server.js`: readonly Fastify API, dynamic MVT routes, cache and viewer assets.
- `src/tile-cache.js`: in-memory LRU cache and in-flight tile request coalescing support.
- `src/export-pmtiles.js`: PMTiles export orchestration and progress.
- `src/pmtiles-worker.js`: worker-thread tile generation for PMTiles export.
- `src/pmtiles.js`: compressed PMTiles archive writer with adaptive directories.
- `src/pmtiles-source.js`: readonly local PMTiles range source for the native Cesium XYZ adapter.

Dynamic serving and PMTiles export both call the same `src/mvt.js` tile generation functions.

### MVT Layer Policies

An unknown layer needs only a manifest descriptor and a readable GeoPackage
table. For example, `{ id: 'observations', table: 'survey_points', minZoom: 8,
maxZoom: 14 }` uses the generic policy automatically, including in PMTiles
workers. Descriptor bounds are inclusive and checked before querying. Public
layer IDs remain separate from SQL table names.

The generic policy reads all spatial candidates without property filters or
enrichment, retains arbitrary MVT-compatible properties, and applies the shared
zoom/detail simplification and total feature budget. It imposes no additional
per-layer quota or minimum feature size. Equal priorities preserve input order.

The four existing encoder functions (`encodeMvtTile`, `encodeMvtTileWithStats`,
`encodeMvtTileSet`, `encodeMvtTileSetWithStats`) accept an optional
`options.getLayerPolicy(layerId, descriptor)` callback. `descriptor` is the
requested layer's reader metadata, or `undefined` for aliases/derived IDs not
declared in the manifest. The callback returns an optional `MvtLayerPolicy`:

| Optional hook | Meaning |
| --- | --- |
| `sourceLayer` | Public reader ID for a derived output layer |
| `aliases` | Fallback source IDs after an exact metadata match |
| `readFeatures(reader, context)` | Return `{ features, originalFeatureCount }`; can use the reader's declarative SQL filters |
| `featureLimit(z)` | Per-layer candidate limit before the global budget |
| `featurePriority(feature, z)` | Descending priority for both budgets; default `100` |
| `toleranceScale(geometryType, z)` | Multiplier for the shared simplification tolerance |
| `minFeatureSize(geometryType, z)` | Minimum bbox span in 4096-unit tile coordinates; default `0` |
| `prepareFeatures(features)` | Transform selected features before simplification and clipping |

The read context contains `layerId` (output ID), `sourceLayer` (resolved reader
ID), `descriptor` (source metadata), buffered EPSG:4326 `bbox`, `z`, `style`, and
`debugLabels`. Both declared output and source descriptor zoom bounds apply.
Use `originalFeatureCount` for the count before policy post-query filtering.
Hooks are synchronous and should return new features when modifying them.

```js
import { encodeMvtTile } from './src/mvt.js';
import { getOsmLayerPolicy } from './src/mvt-osm-policy.js';

const buffer = encodeMvtTile(reader, 'observations', z, x, y, {
  getLayerPolicy(id, descriptor) {
    if (descriptor?.source === 'survey') {
      return {
        readFeatures(reader, { sourceLayer, bbox }) {
          const features = reader.getTileFeatures(sourceLayer, bbox, {
            all: [{ column: 'quality', minNumber: 0.8 }]
          });
          return { features, originalFeatureCount: features.length };
        }
      };
    }
    return getOsmLayerPolicy(id);
  }
});
```

Omitting the callback preserves all built-in OSM policies. Returning `undefined`
or `{}` selects generic behavior for that ID; delegate to `getOsmLayerPolicy`
when extending the defaults. Functions are not stored in manifest JSON. Custom
callbacks are an encoder API; server configuration and PMTiles worker transport
do not yet accept them. Existing serving/export paths use the default resolver,
which already supports unknown layers. Style property hiding stays in the
GeoPackage reader and applies to either policy.

`labelAnchorForGeometry` remains exported from `src/mvt.js` for existing callers.
The OSM regression fixtures record pre-extraction MVT byte hashes, query hashes
and statistics across zoom thresholds, detail modes, budgets and label layers.

## 3D Tiles Pipeline

See [Static Cesium delivery](cesium.md) for the public API, representations and styling contract.
The normal Cesium path has no vector-tile provider or PMTiles extraction endpoint.


- `src/3dtiles/export.js`: 3D Tiles export orchestration.
- `src/3dtiles/gpkg-buildings.js`: readonly building queries and height extraction.
- `src/3dtiles/gpkg-features.js`: readonly feature queries for non-building layers.
- `src/3dtiles/extrude.js`: building footprint extrusion.
- `src/3dtiles/clipper-surfaces.js`: independent buffered/dissolved surface utility; the static context exporter keeps per-feature bands to preserve metadata.
- `src/3dtiles/flat.js`: polygon surfaces with holes and buffered line bands.
- `src/3dtiles/glb.js`: minimal unlit GLB generation.
- `src/3dtiles/b3dm.js`: B3DM with standard per-feature batch tables.
- `src/3dtiles/pnts.js`: batched static point content.
- `src/3dtiles/context-mesh.js`: generic per-feature meshes with batch IDs; spatial ownership and bounded batching live in the exporter.
- `src/3dtiles/tileset.js`: tileset JSON generation.

The default context uses native vector points, lines and polygons. `vector-context.js` selects occupied MVT LODs at build time; `create-tileset.js` owns the hierarchy, and `vector/` owns the format. Extruded geometry retains the mesh encoder.

See [format and compatibility notes](cesium-format.md). The optional mesh context encoder remains available for conventional geometry and polygon cases affected by the vector runtime.

## Package Layout

```text
example.mapzero/
  data.gpkg
  manifest.json
  tiles.pmtiles
  3dtiles/
  styles/
```

`data.gpkg` is the source of truth after build. PMTiles and supported 3D Tiles outputs can be regenerated from it without re-importing the original source.

## Serving Modes

`map-zero` supports two deployment models:

- **Dynamic local server**: Node reads `data.gpkg` and generates MVT on demand.
- **Static/serverless hosting**: exported `tiles.pmtiles` and `3dtiles/` are served as static files.

PMTiles and 3D Tiles do not require a map-zero runtime server after export. The local server remains useful for inspection, development, and dynamic GeoPackage-backed tiles.

## Refactor Notes

- `src/mvt-osm-policy.js`: existing OSM rules remain together behind one resolver; further subdivision is optional. Custom encoder callbacks are not transported to PMTiles workers or exposed through server configuration.
- `src/osm.js`: streamed parser and disk-backed build pipeline are coupled. A future refactor can split temp-store access and geometry builders.
- `src/export-pmtiles.js`: export planning, worker scheduling and PMTiles staging are coupled. A future refactor can split estimation/progress from worker orchestration.
- `packages/ol/src/index.js`: source creation, style interpretation and layer creation are coupled. A future refactor can split source adapters from WebGL style generation.

These are implementation notes, not public API.

### Custom OL PMTiles sources and rendering properties

The public `map-zero/ol/pmtiles` module provides `createPmtilesVectorSource` and
`withFeatureZoomVisibility`. HTTP uses PMTiles FetchSource, File/Blob uses its
slice-backed FileSource, and custom range Sources are accepted. ARINC or other
application cartography is supplied by the caller. The existing OL renderer
shares the extracted MVT tile loader; failed reads emit tile errors, while absent
archive entries produce empty tiles.

A layer's optional `tileProperties: string[]` projects MVT properties without
altering GeoPackage storage. `id`, `mapzero_geometry` and mapped feature zoom
columns survive the projection. Without this option existing property behavior
is unchanged. Archive metadata adds `mapzero:layers` with resolved descriptors;
standard `vector_layers` continues to expose aggregate ranges and declares the
mapped zoom fields as numeric. `isFeatureInZoomRange(layer, get, zoom)` in core
(and the manifest public API) supplies the inclusive actual-view visibility rule.
